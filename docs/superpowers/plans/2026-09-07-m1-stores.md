# M1 Stores Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `packages/store`, the Postgres home of every observation, tag,
trigger and audit entry the engine produces, with each of the milestone's
invariants held by the database rather than by a caller's good manners.

**Architecture:** Nine tables plus a day-seal table, created by plain SQL
migrations applied by our own runner. Observations are stored whole as an
AES-256-GCM blob under a per-namespace data key, with a handful of derived
columns beside them for querying. Append-only, chain integrity and the
promotion timestamp are enforced by triggers that raise; the application maps
each SQLSTATE to a named error. Tag strength is never stored, only derived.

**Tech Stack:** TypeScript on Node 22, pnpm workspaces, PostgreSQL 17, `kysely`
for typed queries, `pg` for the driver, `zod` via `@nonametrust/schema`, vitest.

**Spec:** `docs/superpowers/specs/2026-09-07-m1-stores-design.md`

## Global Constraints

- Node 22 LTS. pnpm workspaces. TypeScript strict mode with `isolatedModules`.
- `exactOptionalPropertyTypes` is on. A field typed as optional cannot be
  assigned `undefined` explicitly.
- Every package's `tsconfig.json` excludes `src/**/*.test.ts` and the seven
  sibling patterns so tests never reach `dist`. Its `tsconfig.test.json`
  **must** set `"exclude": []`, because `extends` inherits the build config's
  exclusion and would otherwise drop tests from typechecking while `tsc` still
  exits zero. This is carried note 5 from M0.
- Continuous integration runs `pnpm build` **before** `pnpm typecheck`, because
  packages resolve through `dist` with no source fallback. Do not reorder.
  This is carried note 6 from M0.
- A new package brings at least one test in the commit that creates it.
  `vitest run` exits 1 on zero test files, deliberately. Carried note 4 from M0.
- Licence Apache-2.0 on every package.
- `Date.now()` never appears in `packages/store` outside `clock.test.ts`. Time
  enters through the injected `Clock`.
- Tag strength is never persisted.
- No `UPDATE` and no `DELETE` on `observation`.
- Suppression lowers strength through accelerated decay. Nothing is deleted.
- All code, comments, identifiers and documentation in English. Board items and
  messages to collaborators in Turkish.
- No tracked file may contain a checksum-valid or shape-valid Stellar account
  identifier. `gates/no-stellar-address.test.ts` enforces it over every tracked
  file. A test needing a real-shaped key generates it at run time.

## SQLSTATE allocation

Fixed once, here, so that no two tasks pick the same code.

| Code | Error class | Raised by |
|---|---|---|
| `NNT01` | `AppendOnlyViolation` | the `observation` and `audit_entry` write guards |
| `NNT02` | `ChainBroken` | the audit chain link check |
| `NNT03` | `ChainBroken` | the audit entry hash check |
| `NNT04` | `TimestampAltered` | the `permanent_record` promotion check |

`NamespaceShredded` and `MigrationDrift` are raised in TypeScript, not by the
database, and carry no SQLSTATE. There is no duplicate-observation error: a
repeated source event is the indexer's normal retry path, so `append` returns
the stored observation with `created: false` rather than raising.

```ts
import { readdirSync, readFileSync, statSync } from "node:fs";
import { join, relative } from "node:path";
import { fileURLToPath } from "node:url";
import { describe, it, expect } from "vitest";

// `datedAt` in packages/schema/src/timing.ts is the only reader of a date off
// an observation. After narrowing on evidenceKind, observedAt and validFrom
// are both readable with full type support, and reading validFrom where a date
// was meant is the substitution that produced the study's S3 defect.
//
// This gate lived inside packages/schema and derived its scan root from its
// own location, so it covered one package. The arithmetic most likely to break
// the claim is the window and decay code, which lands in other packages, so
// the gate sits at the repository root and scans every package instead. A new
// package enters under it on the day it is created.
//
// Exemptions are paths relative to packages/, never basenames: a later
// store/src/timing.ts must not inherit schema/src/timing.ts's exemption.
const packagesDir = fileURLToPath(new URL("../packages/", import.meta.url));
const EXEMPT = new Set([
  "schema/src/observation.ts", // defines the fields
  "schema/src/timing.ts",      // reads them, and is the only module that may
]);

const SOURCE = /\.(ts|mts|cts|tsx)$/;
const TEST = /\.(test|spec)\.(ts|mts|cts|tsx)$/;
const DATE_FIELDS = /\b(observedAt|validFrom|validUntil)\b/;

function packageSrcDirs(): string[] {
  return readdirSync(packagesDir, { withFileTypes: true })
    .filter((d) => d.isDirectory())
    .map((d) => join(packagesDir, d.name, "src"))
    .filter((p) => {
      try { return statSync(p).isDirectory(); } catch { return false; }
    });
}

describe("dates on an observation", () => {
  it("scans more than one package, so the gate cannot pass by scanning nothing", () => {
    const dirs = packageSrcDirs();
    expect(dirs.length, "no packages/*/src found; the gate is scanning nothing").toBeGreaterThan(0);
    expect(dirs.some((d) => d.endsWith("schema/src"))).toBe(true);
  });

  it("are read only by datedAt in packages/schema/src/timing.ts", () => {
    const offenders: string[] = [];
    for (const srcDir of packageSrcDirs()) {
      for (const entry of readdirSync(srcDir, { recursive: true, withFileTypes: true })) {
        if (!SOURCE.test(entry.name) || TEST.test(entry.name)) continue;
        const file = join(entry.parentPath, entry.name);
        // stat follows a symlink; the dirent's own isFile() is false for one,
        // which let a symlinked module ship through tsc while a gate skipped it.
        if (!statSync(file).isFile()) continue;
        const rel = relative(packagesDir, file);
        if (EXEMPT.has(rel)) continue;
        readFileSync(file, "utf8").split("\n").forEach((line, i) => {
          if (DATE_FIELDS.test(line)) offenders.push(`${rel}:${i + 1}: ${line.trim()}`);
        });
      }
    }
    expect(
      offenders,
      "these lines read a date field off an observation; go through datedAt() in packages/schema/src/timing.ts instead:\n" +
        offenders.join("\n"),
    ).toEqual([]);
  });
});
```

`packages/store/scripts/dev-db.sh`, then `chmod +x` it:

```bash
#!/usr/bin/env bash
# A Postgres cluster that belongs to this repository and to no machine.
#
# It listens on loopback TCP rather than on a Unix socket, and that is not a
# preference: a socket path may not exceed 103 bytes, and a socket directory
# inside a checkout under a long path exceeds it and fails at connect time with
# an error that reads like a permissions problem.
#
# The locale is C so the cluster's own default collation is deterministic. The
# explicit COLLATE "C" in the migrations stays regardless; the column must not
# depend on how the cluster was initialised.
set -euo pipefail

PORT="${NNT_DEV_DB_PORT:-55432}"
HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PGDATA="$HERE/../.pgdata"
LOG="$HERE/../.pgdata.log"
PGBIN="${NNT_PG_BIN:-/opt/homebrew/opt/postgresql@17/bin}"
export PATH="$PGBIN:$PATH"

case "${1:-up}" in
  up)
    if [ ! -d "$PGDATA" ]; then
      initdb -D "$PGDATA" -A trust -U nnt --encoding=UTF8 --locale=C >/dev/null
    fi
    if ! pg_ctl -D "$PGDATA" status >/dev/null 2>&1; then
      pg_ctl -D "$PGDATA" -l "$LOG" \
        -o "-p $PORT -c listen_addresses=127.0.0.1" start >/dev/null
    fi
    createdb -h 127.0.0.1 -p "$PORT" -U nnt nnt_test 2>/dev/null || true
    echo "export NNT_TEST_DATABASE_URL=postgres://nnt@127.0.0.1:$PORT/nnt_test"
    ;;
  down)
    pg_ctl -D "$PGDATA" stop >/dev/null 2>&1 || true
    ;;
  destroy)
    pg_ctl -D "$PGDATA" stop >/dev/null 2>&1 || true
    rm -rf "$PGDATA" "$LOG"
    ;;
  *)
    echo "usage: dev-db.sh [up|down|destroy]" >&2
    exit 2
    ;;
esac
```

- [ ] **Step 4: Write the clock and its test**

`packages/store/src/clock.ts`:

```ts
/**
 * Time enters the store through this interface and through no other route.
 * `Date.now()` does not appear in this package outside clock.test.ts: the
 * day-12 / day-21 scenario runs twenty-one simulated days in milliseconds,
 * which is impossible if any component reads the wall clock directly.
 */
export interface Clock {
  now(): Date;
}

export const systemClock: Clock = {
  now: () => new Date(),
};

export interface FixedClock extends Clock {
  advance(ms: number): void;
}

export function fixedClock(start: Date): FixedClock {
  let t = start.getTime();
  return {
    now: () => new Date(t),
    advance: (ms: number) => {
      t += ms;
    },
  };
}
```

`packages/store/src/clock.test.ts`:

```ts
import { describe, it, expect } from "vitest";
import { fixedClock, systemClock } from "./clock.js";

describe("fixedClock", () => {
  it("does not move on its own", () => {
    const c = fixedClock(new Date("2026-09-07T00:00:00.000Z"));
    const a = c.now();
    const b = c.now();
    expect(b.getTime()).toBe(a.getTime());
  });

  it("advances by exactly what it is told, so twenty-one days cost nothing", () => {
    const c = fixedClock(new Date("2026-09-07T00:00:00.000Z"));
    c.advance(21 * 24 * 60 * 60 * 1000);
    expect(c.now().toISOString()).toBe("2026-09-28T00:00:00.000Z");
  });

  it("hands out a copy, so a caller cannot move the clock by mutating its answer", () => {
    const c = fixedClock(new Date("2026-09-07T00:00:00.000Z"));
    c.now().setFullYear(2000);
    expect(c.now().toISOString()).toBe("2026-09-07T00:00:00.000Z");
  });
});

describe("systemClock", () => {
  // This file is the one place in the package permitted to call Date.now(),
  // and only to check systemClock against it.
  it("returns a date near now", () => {
    expect(Math.abs(systemClock.now().getTime() - Date.now())).toBeLessThan(1000);
  });
});
```

- [ ] **Step 6: Write the errors module**

`packages/store/src/errors.ts`:

```ts
/**
 * Every invariant the database holds raises a distinct SQLSTATE, and each maps
 * to a class here. Tests assert on the class and never on the message text, so
 * that rewording a message is not a red suite and swallowing a violation is
 * not a green one.
 */
export class StoreError extends Error {}

export class AppendOnlyViolation extends StoreError {}
export class ChainBroken extends StoreError {}
export class TimestampAltered extends StoreError {}
export class NamespaceShredded extends StoreError {}
export class MigrationDrift extends StoreError {}

const BY_SQLSTATE: Record<string, new (m: string) => StoreError> = {
  NNT01: AppendOnlyViolation,
  NNT02: ChainBroken,
  NNT03: ChainBroken,
  NNT04: TimestampAltered,
};

/**
 * Returns a named error for a Postgres error this package raised, and null for
 * anything else. Null rather than a generic wrapper: an error we did not
 * design is rethrown unchanged, because flattening an unknown driver failure
 * into a store error hides it.
 */
export function mapPgError(e: unknown): StoreError | null {
  if (typeof e !== "object" || e === null) return null;
  const code = (e as { code?: unknown }).code;
  if (typeof code !== "string") return null;
  const Ctor = BY_SQLSTATE[code];
  if (!Ctor) return null;
  const message = (e as { message?: unknown }).message;
  return new Ctor(typeof message === "string" ? message : code);
}
```

`packages/store/src/migrate.ts`:

```ts
import { createHash } from "node:crypto";
import { readdirSync, readFileSync } from "node:fs";
import { join } from "node:path";
import { sql } from "kysely";
import type { Db } from "./db.js";
import { MigrationDrift } from "./errors.js";

// One arbitrary but fixed key, so two processes migrating at once serialise
// rather than racing to create the same table.
const LOCK_KEY = 81402026;

/**
 * Applies every unapplied file in `dir`, in filename order, each in its own
 * transaction. Returns the filenames it applied, empty on a second run.
 *
 * A file whose recorded hash no longer matches its content stops the run. An
 * edited migration is a different migration, and finding that out in
 * production is worse than a failed start.
 */
export async function migrate(db: Db, dir: string): Promise<string[]> {
  await sql`select pg_advisory_lock(${LOCK_KEY})`.execute(db);
  try {
    await sql`
      create table if not exists schema_migration (
        filename   text primary key,
        sha256     text not null,
        applied_at timestamptz not null default now()
      )
    `.execute(db);

    const recorded = new Map(
      (await db.selectFrom("schema_migration").select(["filename", "sha256"]).execute()).map(
        (r) => [r.filename, r.sha256] as const,
      ),
    );

    const files = readdirSync(dir).filter((f) => f.endsWith(".sql")).sort();
    const applied: string[] = [];

    for (const filename of files) {
      const body = readFileSync(join(dir, filename), "utf8");
      const digest = createHash("sha256").update(body).digest("hex");
      const seen = recorded.get(filename);
      if (seen !== undefined) {
        if (seen !== digest) {
          throw new MigrationDrift(
            `${filename} was applied with different content (recorded ${seen}, found ${digest}). ` +
              "An edited migration is a different migration; add a new file instead.",
          );
        }
        continue;
      }
      await db.transaction().execute(async (trx) => {
        await sql.raw(body).execute(trx);
        await trx
          .insertInto("schema_migration")
          .values({ filename, sha256: digest, applied_at: new Date() })
          .execute();
      });
      applied.push(filename);
    }
    return applied;
  } finally {
    await sql`select pg_advisory_unlock(${LOCK_KEY})`.execute(db);
  }
}
```

Note the ordering inside the transaction: the file runs first and the record is
written second, both under one transaction, so a failing file leaves no record.

```ts
/**
 * A private schema per test file, with every migration applied into it and
 * dropped afterwards. Isolation is a fresh schema rather than TRUNCATE,
 * because TRUNCATE bypasses row triggers and would let a test reach a state
 * production cannot.
 *
 * The schema name goes into the connection string rather than being set with
 * `set search_path`, because the driver pools connections and a session
 * setting applies to one of them.
 */
export async function withSchema(name: string): Promise<{ db: Db; done: () => Promise<void> }> {
  const base = requireTestUrl();
  const admin = openDb(base);
  await sql.raw(`drop schema if exists ${name} cascade`).execute(admin);
  await sql.raw(`create schema ${name}`).execute(admin);
  await admin.destroy();

  const separator = base.includes("?") ? "&" : "?";
  const db = openDb(`${base}${separator}options=-c%20search_path%3D${name}`);
  await migrate(db, MIGRATIONS);

  return {
    db,
    done: async () => {
      await db.destroy();
      const cleanup = openDb(base);
      await sql.raw(`drop schema if exists ${name} cascade`).execute(cleanup);
      await cleanup.destroy();
    },
  };
}
```

`packages/store/src/crypto.ts`:

```ts
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";

const ALGORITHM = "aes-256-gcm";
const KEY_BYTES = 32;
const NONCE_BYTES = 12;
const TAG_BYTES = 16;
const WRAP_VERSION = 1;

// The idempotency key joins its parts on a separator that cannot occur inside
// a field, for a reason the schema states: without one, two adjacent parts can
// be re-partitioned into a different pair with the same concatenation. The
// associated data has the same problem and takes the same answer. A namespace
// id is a uuid here and an idempotency key is hex, so neither can contain the
// separator.
const SEPARATOR = "|";

export interface Sealed {
  nonce: Buffer;
  ciphertext: Buffer;
  tag: Buffer;
}

export interface KeyRing {
  wrap(dataKey: Buffer): Buffer;
  unwrap(wrapped: Buffer): Buffer;
}

export function newDataKey(): Buffer {
  return randomBytes(KEY_BYTES);
}

export function payloadAad(namespaceId: string, idempotencyKey: string): Buffer {
  return Buffer.from([namespaceId, idempotencyKey].join(SEPARATOR), "utf8");
}

export function seal(dataKey: Buffer, plaintext: string, aad: Buffer): Sealed {
  const nonce = randomBytes(NONCE_BYTES);
  const cipher = createCipheriv(ALGORITHM, dataKey, nonce);
  cipher.setAAD(aad);
  const ciphertext = Buffer.concat([cipher.update(plaintext, "utf8"), cipher.final()]);
  return { nonce, ciphertext, tag: cipher.getAuthTag() };
}

export function open(dataKey: Buffer, sealed: Sealed, aad: Buffer): string {
  const decipher = createDecipheriv(ALGORITHM, dataKey, sealed.nonce);
  decipher.setAAD(aad);
  decipher.setAuthTag(sealed.tag);
  return Buffer.concat([decipher.update(sealed.ciphertext), decipher.final()]).toString("utf8");
}

/**
 * There is no default master key and no development fallback. A fallback key
 * is a key that reaches production.
 *
 * The wrapped form carries a version byte so that key rotation is a decode
 * branch rather than a migration over every stored row.
 */
export function keyRingFromEnv(env: NodeJS.ProcessEnv = process.env): KeyRing {
  const raw = env.NNT_MASTER_KEY;
  if (!raw) {
    throw new Error("NNT_MASTER_KEY is not set; the store does not start without a master key");
  }
  const master = Buffer.from(raw, "base64");
  if (master.length !== KEY_BYTES) {
    throw new Error(`NNT_MASTER_KEY must decode to 32 bytes, got ${master.length}`);
  }
  return {
    wrap(dataKey: Buffer): Buffer {
      const nonce = randomBytes(NONCE_BYTES);
      const cipher = createCipheriv(ALGORITHM, master, nonce);
      const body = Buffer.concat([cipher.update(dataKey), cipher.final()]);
      return Buffer.concat([Buffer.from([WRAP_VERSION]), nonce, cipher.getAuthTag(), body]);
    },
    unwrap(wrapped: Buffer): Buffer {
      if (wrapped[0] !== WRAP_VERSION) {
        throw new Error(`unknown wrapped-key version ${wrapped[0]}`);
      }
      const nonce = wrapped.subarray(1, 1 + NONCE_BYTES);
      const tag = wrapped.subarray(1 + NONCE_BYTES, 1 + NONCE_BYTES + TAG_BYTES);
      const body = wrapped.subarray(1 + NONCE_BYTES + TAG_BYTES);
      const decipher = createDecipheriv(ALGORITHM, master, nonce);
      decipher.setAuthTag(tag);
      return Buffer.concat([decipher.update(body), decipher.final()]);
    },
  };
}
```

`packages/store/migrations/0001_namespace.sql`:

```sql
-- A namespace is a counterparty's identity, and the identifier is compared
-- byte for byte.
--
-- COLLATE "C" is written out rather than relied upon. Equality under any
-- deterministic collation is already byte equality, so on a normally created
-- cluster this column behaves correctly without the clause. It is here because
-- the failure it prevents is silent and total: a cluster created with a
-- nondeterministic ICU collation would fold two spellings into one logical
-- namespace, and evidence about two counterparties would be summed into one.
-- That is the exact failure the idempotency key's namespace part exists to
-- prevent, and the two now agree instead of one assuming the other.
--
-- Postgres text cannot hold a NUL byte, so the schema's NUL rule needs no
-- restatement here.
create table namespace (
  namespace_id     uuid primary key,
  kind             text not null check (kind in ('wallet','domain','endpoint','merchant')),
  ns_id            text collate "C" not null check (length(ns_id) > 0),
  -- Null once shredded. The key lives here and not on observation because
  -- shredding is an UPDATE and observation accepts none.
  data_key_wrapped bytea,
  key_shredded_at  timestamptz,
  created_at       timestamptz not null,
  constraint namespace_identity unique (kind, ns_id),
  constraint namespace_shred_consistent
    check ((data_key_wrapped is null) = (key_shredded_at is not null))
);
```

```ts
import { randomUUID } from "node:crypto";
import type { NamespaceRef } from "@nonametrust/schema";
import type { Clock } from "../clock.js";
import type { Db } from "../db.js";
import { newDataKey, type KeyRing } from "../crypto.js";
import { NamespaceShredded } from "../errors.js";

export interface StoredNamespace {
  namespaceId: string;
  kind: string;
  nsId: string;
  shreddedAt: Date | null;
}

export class NamespaceRepository {
  constructor(
    private readonly db: Db,
    private readonly ring: KeyRing,
    private readonly clock: Clock,
  ) {}

  /**
   * Returns the namespace for this reference, creating it with a fresh data
   * key on first sight.
   *
   * Insert-then-select rather than an upsert on purpose: an upsert that wrote
   * `data_key_wrapped` on conflict would mint a new key for a shredded
   * namespace and quietly undo the erasure. `do nothing` leaves a shredded row
   * exactly as it was.
   */
  async ensure(ref: NamespaceRef): Promise<StoredNamespace> {
    await this.db
      .insertInto("namespace")
      .values({
        namespace_id: randomUUID(),
        kind: ref.kind,
        ns_id: ref.id,
        data_key_wrapped: this.ring.wrap(newDataKey()),
        key_shredded_at: null,
        created_at: this.clock.now(),
      })
      .onConflict((oc) => oc.constraint("namespace_identity").doNothing())
      .execute();
    const found = await this.find(ref.kind, ref.id);
    if (!found) throw new Error(`namespace ${ref.kind} disappeared after insert`);
    return found;
  }

  async find(kind: string, id: string): Promise<StoredNamespace | null> {
    const row = await this.db
      .selectFrom("namespace")
      .select(["namespace_id", "kind", "ns_id", "key_shredded_at"])
      .where("kind", "=", kind)
      .where("ns_id", "=", id)
      .executeTakeFirst();
    return row
      ? {
          namespaceId: row.namespace_id,
          kind: row.kind,
          nsId: row.ns_id,
          shreddedAt: row.key_shredded_at,
        }
      : null;
  }

  async dataKey(namespaceId: string): Promise<Buffer> {
    const row = await this.db
      .selectFrom("namespace")
      .select(["data_key_wrapped"])
      .where("namespace_id", "=", namespaceId)
      .executeTakeFirst();
    if (!row) throw new Error(`no namespace ${namespaceId}`);
    if (row.data_key_wrapped === null) {
      throw new NamespaceShredded(
        `namespace ${namespaceId} was shredded; its payloads are unreadable`,
      );
    }
    return this.ring.unwrap(row.data_key_wrapped);
  }

  /**
   * Crypto-shredding. Dropping the wrapped key makes every payload for this
   * namespace permanently unreadable while the rows stay in place, so counts,
   * timestamps and the audit chain remain intact and verifiable. That is the
   * correct shape for an erasure request against an append-only ledger.
   *
   * Idempotent: a repeated erasure request is not an error.
   */
  async shred(namespaceId: string): Promise<void> {
    await this.db
      .updateTable("namespace")
      .set({ data_key_wrapped: null, key_shredded_at: this.clock.now() })
      .where("namespace_id", "=", namespaceId)
      .where("data_key_wrapped", "is not", null)
      .execute();
  }
}
```

```sql
-- The whole validated observation is stored as one encrypted blob, with a few
-- derived columns beside it for querying. Reading decrypts the blob and
-- re-parses it through the schema, so the round trip proves the stored form
-- and the schema agree rather than proving a hand-written mapper is its own
-- inverse.
--
-- dated_at comes from datedAt() in @nonametrust/schema and is null for a
-- state, so this package reaches an observation's dates through that one
-- function and needs no exemption in gates/single-date-reader.test.ts. That
-- gate scans TypeScript only, which is why this SQL comment may name the
-- fields plainly while the TypeScript beside it may not: the gate matches
-- the names inside comments and string literals as well as in code.
create table observation (
  observation_id     uuid primary key,
  idempotency_key    text collate "C" not null unique,
  namespace_id       uuid not null references namespace (namespace_id),
  channel            text not null,
  kind               text not null,
  evidence_kind      text not null check (evidence_kind in ('event','state')),
  dated_at           timestamptz,
  ingested_at        timestamptz not null,
  payload_nonce      bytea not null,
  payload_tag        bytea not null,
  payload_ciphertext bytea not null,
  constraint observation_state_is_undated
    check (evidence_kind = 'event' or dated_at is null)
);

create index observation_by_namespace on observation (namespace_id, dated_at desc);

-- Append-only, held by the database.
--
-- A rewrite rule of the DO INSTEAD NOTHING form is deliberately not used: it
-- swallows the write silently, which turns a loud bug into a quiet one. This
-- raises, and the application maps NNT01 to AppendOnlyViolation.
--
-- The second line of defence named in the design is revoking UPDATE and DELETE
-- from the deployed application role. That belongs to role setup, not to this
-- migration, and the test cluster runs as the owner so it cannot be exercised
-- here. The trigger is the tested half; say so in the ledger.
create function observation_append_only() returns trigger language plpgsql as $$
begin
  raise exception using
    errcode = 'NNT01',
    message = 'observation is append-only: ' || tg_op || ' is refused';
end
$$;

create trigger observation_no_update
  before update or delete on observation
  for each row execute function observation_append_only();
```

```ts
import { randomUUID } from "node:crypto";
import {
  datedAt, deriveIdempotencyKey, observationSchema,
  type Observation, type WireObservation,
} from "@nonametrust/schema";
import type { Clock } from "../clock.js";
import type { Db } from "../db.js";
import { open, payloadAad, seal } from "../crypto.js";
import { mapPgError } from "../errors.js";
import type { NamespaceRepository } from "./namespace.js";

export interface AppendResult {
  observation: Observation;
  created: boolean;
}

interface EncryptedRow {
  namespace_id: string;
  idempotency_key: string;
  payload_nonce: Buffer;
  payload_tag: Buffer;
  payload_ciphertext: Buffer;
}

export class ObservationRepository {
  constructor(
    private readonly db: Db,
    private readonly namespaces: NamespaceRepository,
    private readonly clock: Clock,
  ) {}

  /**
   * Writing the same source event twice is the indexer's normal retry path,
   * not a defect, so a repeat returns the stored observation and reports
   * `created: false` rather than raising. The distinction between "already
   * stored" and "conflicting" is drawn on the idempotency key alone, which is
   * what the key exists for.
   */
  async append(wire: WireObservation): Promise<AppendResult> {
    const parsed = observationSchema.parse(wire) as Observation;
    const key = deriveIdempotencyKey(parsed.source, parsed.channel, parsed.namespace);

    const existing = await this.byIdempotencyKey(key);
    if (existing) return { observation: existing, created: false };

    const ns = await this.namespaces.ensure(parsed.namespace);
    const observationId = randomUUID();
    const ingestedAt = this.clock.now();
    const stored = {
      ...parsed,
      observationId,
      idempotencyKey: key,
      ingestedAt: ingestedAt.toISOString(),
    } as Observation;

    const dataKey = await this.namespaces.dataKey(ns.namespaceId);
    const sealed = seal(dataKey, JSON.stringify(stored), payloadAad(ns.namespaceId, key));
    // datedAt is the single reader of a date off an observation, and calling
    // it here is why this package needs no exemption in the repository's
    // single-date-reader gate. Note that the gate matches those field names
    // inside comments too, so this one describes the rule without naming
    // them.
    const dated = datedAt(stored);

    try {
      await this.db
        .insertInto("observation")
        .values({
          observation_id: observationId,
          idempotency_key: key,
          namespace_id: ns.namespaceId,
          channel: stored.channel,
          kind: stored.kind,
          evidence_kind: stored.evidenceKind,
          dated_at: dated === null ? null : new Date(dated),
          ingested_at: ingestedAt,
          payload_nonce: sealed.nonce,
          payload_tag: sealed.tag,
          payload_ciphertext: sealed.ciphertext,
        })
        .execute();
    } catch (e) {
      // A concurrent writer may have inserted the same key between the read
      // above and this insert. That is a duplicate, not a failure.
      const again = await this.byIdempotencyKey(key);
      if (again) return { observation: again, created: false };
      throw mapPgError(e) ?? e;
    }
    return { observation: stored, created: true };
  }

  async get(observationId: string): Promise<Observation> {
    const row = await this.db
      .selectFrom("observation")
      .select([
        "namespace_id", "idempotency_key",
        "payload_nonce", "payload_tag", "payload_ciphertext",
      ])
      .where("observation_id", "=", observationId)
      .executeTakeFirst();
    if (!row) throw new Error(`no observation ${observationId}`);
    return this.decrypt(row);
  }

  async byIdempotencyKey(key: string): Promise<Observation | null> {
    const row = await this.db
      .selectFrom("observation")
      .select([
        "namespace_id", "idempotency_key",
        "payload_nonce", "payload_tag", "payload_ciphertext",
      ])
      .where("idempotency_key", "=", key)
      .executeTakeFirst();
    return row ? this.decrypt(row) : null;
  }

  private async decrypt(row: EncryptedRow): Promise<Observation> {
    // Raises NamespaceShredded when the key is gone, which is the whole point
    // of shredding: the row survives and the content does not.
    const dataKey = await this.namespaces.dataKey(row.namespace_id);
    const json = open(
      dataKey,
      { nonce: row.payload_nonce, tag: row.payload_tag, ciphertext: row.payload_ciphertext },
      payloadAad(row.namespace_id, row.idempotency_key),
    );
    return observationSchema.parse(JSON.parse(json)) as Observation;
  }
}
```

```sql
-- A tag is a limbo entry. It stores what it was tagged with and when, and it
-- does not store how strong it is now: strength is a function of g0, elapsed
-- time, the channel half-life and the suppression factor, so any historical
-- strength is reproducible and no background writer has to exist.
--
-- Suppression is accelerated decay, not deletion. suppression_factor
-- multiplies elapsed time in the decay, so a suppressed tag falls faster and
-- never disappears by being removed.
create table tag (
  tag_id             uuid primary key,
  namespace_id       uuid not null references namespace (namespace_id),
  observation_id     uuid not null references observation (observation_id),
  channel            text not null,
  g0                 double precision not null check (g0 >= 0),
```

`packages/store/src/strength.ts`:

```ts
import type { StoredTag } from "./repositories/tag.js";

/**
 * A tag's strength at an instant, derived and never stored.
 *
 * Deriving rather than storing has two consequences the design depends on.
 * The nightly job becomes the only writer, so a determinism test over a fixed
 * corpus is meaningful. And any historical strength is reproducible from the
 * audit log, because nothing was overwritten to produce today's number.
 *
 * Suppression multiplies elapsed time rather than subtracting from g0, so a
 * suppressed tag decays faster and never reaches zero. That is what makes
 * suppression accelerated decay rather than deletion.
 *
 * Before `taggedAt` the strength is g0: a tag has no history before it
 * existed, and returning something larger would let a clock skew invent
 * evidence.
 */
export function strengthAt(tag: StoredTag, instant: Date, halfLifeMs: number): number {
  if (halfLifeMs <= 0) throw new RangeError("halfLifeMs must be positive");
  const elapsed = instant.getTime() - tag.taggedAt.getTime();
  if (elapsed <= 0) return tag.g0;
  return tag.g0 * Math.pow(0.5, (elapsed * tag.suppressionFactor) / halfLifeMs);
}
```

beside a dozen SQL triggers is a legibility cost paid on every future read. The
design document calls it `trigger`; this is the one place the two differ, and
it is written down here so the difference is a decision and not a drift.

```sql
-- A promotion preserves the instant the evidence carried, not the instant it
-- was promoted. The day-12 address change surfaces on day twenty-one still
-- dated day twelve; that is the whitepaper's scenario and the reason this
-- column exists.
--
-- The trigger is why it is a claim and not a hope. A test can prove the
-- repository copies the timestamp today; the trigger proves that every writer
-- does, including one written next month against the table directly.
create table permanent_record (
  record_id         uuid primary key,
  observation_id    uuid not null references observation (observation_id),
  namespace_id      uuid not null references namespace (namespace_id),
  original_dated_at timestamptz not null,
  promoted_at       timestamptz not null,
  -- References trigger_event, which migration 0006 creates. The constraint is
  -- added there.
  rescued_by        uuid,
  confidence        double precision not null check (confidence >= 0 and confidence <= 1),
  constraint permanent_record_once unique (observation_id)
);

create function permanent_record_keeps_its_date() returns trigger language plpgsql as $$
declare source_dated timestamptz;
begin
  select dated_at into source_dated from observation where observation_id = new.observation_id;
  if source_dated is distinct from new.original_dated_at then
    raise exception using
      errcode = 'NNT04',
      message = 'a promotion must carry the observation''s own instant, not the promotion instant';
  end if;
  return new;
end
$$;

create trigger permanent_record_date_preserved
  before insert or update on permanent_record
  for each row execute function permanent_record_keeps_its_date();
```

`packages/store/migrations/0005_audit.sql`:

```sql
create table audit_entry (
  seq            bigint generated always as identity primary key,
  occurred_at    timestamptz not null,
  policy_version text not null,
  kind           text not null,
  body           jsonb not null,
  -- The exact string that was hashed. It is stored rather than recomputed
  -- because a chain that must verify in a year cannot rest on a Postgres
  -- version's jsonb rendering staying byte-identical.
  canonical      text not null,
  prev_sha256    bytea not null,
  entry_sha256   bytea not null unique
);

create table audit_day (
  day             date primary key,
  terminal_seq    bigint not null references audit_entry (seq),
  terminal_sha256 bytea not null,
  hmac            bytea not null,
  sealed_at       timestamptz not null
);

create function audit_entry_chain() returns trigger language plpgsql as $$
declare prev bytea; expected bytea;
begin
  -- Two concurrent appends would otherwise read the same predecessor and both
  -- claim to follow it. The lock serialises them for the transaction.
  perform pg_advisory_xact_lock(8140202601);

  select entry_sha256 into prev from audit_entry where seq < new.seq order by seq desc limit 1;
  if prev is null then
    prev := decode(repeat('00', 32), 'hex');
  end if;
  if new.prev_sha256 is distinct from prev then
    raise exception using
      errcode = 'NNT02',
      message = 'audit entry does not follow the chain head';
  end if;

  expected := sha256(new.prev_sha256 || convert_to(new.canonical, 'UTF8'));
  if new.entry_sha256 is distinct from expected then
    raise exception using
      errcode = 'NNT03',
      message = 'audit entry hash does not match its canonical form';
  end if;
  return new;
end
$$;

create trigger audit_entry_chained
  before insert on audit_entry
  for each row execute function audit_entry_chain();

create function audit_entry_append_only() returns trigger language plpgsql as $$
begin
  raise exception using
    errcode = 'NNT01',
    message = 'audit_entry is append-only: ' || tg_op || ' is refused';
end
$$;

create trigger audit_entry_no_rewrite
  before update or delete on audit_entry
  for each row execute function audit_entry_append_only();
```

- [ ] **Step 3: Implement**

`canonicalForm` sorts object keys recursively, keeps array order, renders the
date as ISO 8601 with milliseconds, and joins the five parts with a separator
that cannot occur in any of them. `AuditChain.append` reads the head, computes
`canonical`, computes `sha256(prev || canonical)` in Node, and inserts all
three; the trigger then independently recomputes the hash and refuses a
mismatch, so the two implementations check each other rather than one trusting
the other.

`verify` streams the table in `seq` order, re-derives `canonical` from each
row's own columns, recomputes both hashes and returns the first sequence number
that disagrees, with a reason naming which of the two checks failed.

`sealDay` takes the terminal entry of that day and HMAC-SHA256s its hash under
a key derived from the master key with a fixed, documented label, so the day
seal and the payload keys cannot be confused with each other.

**Why `canonicalForm` has no `seq`:** the identity column is assigned during
the insert, so `append` does not know it beforehand. Reserving it with
`nextval` first would cost a round trip to hash a value the linkage already
encodes. `seq` is therefore excluded, and `verify` re-derives each row's
canonical form from the four fields that are in it.

```sql
-- Welford state, robust state, and the two timescales. Mutable by design: a
-- baseline is current state, not evidence. The arithmetic is M2's.
create table baseline (
  namespace_id uuid not null references namespace (namespace_id),
  channel      text not null,
  aspect       text not null,
  n            bigint not null default 0 check (n >= 0),
  mean         double precision not null default 0,
  m2           double precision not null default 0,
  median_est   double precision,
  mad_est      double precision,
  fast_mean    double precision not null default 0,
  fast_m2      double precision not null default 0,
  slow_mean    double precision not null default 0,
  slow_m2      double precision not null default 0,
  updated_at   timestamptz not null,
  primary key (namespace_id, channel, aspect)
);

-- Named trigger_event and not trigger. `trigger` is a non-reserved keyword and
-- works unquoted, verified on PostgreSQL 17.7, but a table called trigger
-- beside a dozen SQL triggers costs legibility on every future read.
--
-- status and tier are text with a check rather than enum types. A Postgres
-- enum cannot lose a value without rewriting the type, and the tiered failure
-- policy is M3's to settle; a check constraint is a one-line migration to
-- change and an enum is not.
create table trigger_event (
  trigger_id     uuid primary key,
  namespace_id   uuid not null references namespace (namespace_id),
  observation_id uuid not null references observation (observation_id),
  status         text not null check (status in ('candidate','verified','harm_confirmed')),
  tier           text check (tier is null or status = 'harm_confirmed'),
  cluster_id     uuid,
  surprise       double precision not null,
  created_at     timestamptz not null
);

create table volatility (
  namespace_id uuid primary key references namespace (namespace_id),
  q_hat        double precision not null,
  updated_at   timestamptz not null
);

create table hot_window (
  window_id    uuid primary key,
  namespace_id uuid not null references namespace (namespace_id),
  trigger_id   uuid not null references trigger_event (trigger_id),
  opens_at     timestamptz not null,
  closes_at    timestamptz not null,
  scale        double precision not null check (scale > 0),
  constraint hot_window_ordered check (closes_at > opens_at)
);

-- Deferred from 0004: permanent_record.rescued_by points at a trigger, and
-- trigger_event did not exist when that migration ran.
alter table permanent_record
  add constraint permanent_record_rescued_by_fk
  foreign key (rescued_by) references trigger_event (trigger_id);
```

`count` is a reserved-enough word to be worth avoiding as a column name in
hand-written SQL, so the Welford counter is `n`. Keep the TypeScript field
named `count` if that reads better and map it in the repository.
