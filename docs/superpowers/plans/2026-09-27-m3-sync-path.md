# M3, the synchronous path and the brief: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Design authority:** the board card "M3 · Senkron yol ve brief" on
> `github.com/orgs/nonametrust/projects/1`, and §6 of
> `docs/superpowers/specs/2026-09-05-mvp-v0-core-engine-design.md`. This plan was
> written against the SHIPPED CODE rather than against either, which is the rule
> that has now paid four times: M2's plan read against M1's code found two
> contradictions, the storage card's plan found the four its card knew about and
> seven it did not, and the survey behind this plan found that the storage card's
> own §2d had handed M3 a finding that was backwards. Section 1 is what the rule
> produced this time.

**Goal:** the engine's synchronous path. An observation arrives, is folded into
a baseline, is tagged by M2's arithmetic and written by the store as handed; and
a `brief` over the stores returns a graded answer with its reasons and their
sources, with an active tag lowering that counterparty's threshold, and with a
named behaviour per risk tier when a store cannot be reached. At the end of M3
the two verbs the whitepaper promises, `observe` and `brief`, both exist.

**Architecture:** one new package, `packages/engine`, which is the first module
allowed to import BOTH `@nonametrust/store` and `@nonametrust/tagging` — it is
the composition point those two packages were kept apart for. One new versioned
value `BriefPolicy` lives there. One new migration, `0008`, for the one thing
relatedness cannot be computed without. The brief is a pure function: it takes
its instant, its ids and its policy as inputs and returns a value plus a list of
effects, and a thin wrapper performs the effects. Everything invariant stays held
by Postgres; the TypeScript refuses first and names the class.

**Authorities read:** the M3 board card and its 27 September addendum; `docs/superpowers/ledgers/2026-09-12-m2-decisions.md` §"Carried into M3 and the schema card" (615-743); `docs/superpowers/ledgers/2026-09-26-storage-card-decisions.md`; `docs/superpowers/plans/2026-09-21-storage-card.md` §2b (R9-R21), §2c (the limits of crypto-shredding), §2d (what later task texts get wrong AND the eight findings left unfixed); the M1 ledger; the core-engine design §1, §2, §6-§9; every file in `packages/store/src` and `packages/tagging/src`; migrations `0001`-`0007`.

## 1. Findings: where the shipped code contradicts the design, or the design contradicts itself

Each of these was measured against code, with file and line. They are the reason
this plan makes twenty-one rulings before a task starts.

**F1. "A pure function over the stores" and "note the trigger" cannot both be
true.** Design §6:259-268 says the brief is pure and that its flow includes
noting the trigger. Noting a trigger is `TriggerEventRepository.record`
(`store/src/repositories/trigger-event.ts:52`), a write, and its row needs an
`observationId` under a foreign key (`0006:85-87`), so the intent must already
exist as an observation — and `append` refuses a `Transaction`
(`store/src/repositories/observation.ts:153`, R21), as does `AuditChain.append` (`store/src/audit/chain.ts:269`). M1's
own story pins that a brief leaves the tag table byte-for-byte untouched
(`store/src/acceptance.test.ts:379`). So three writes hang off one "pure
function" and two of them cannot share a transaction with anything. Cost of
building on the design's sentence: three wrappers each invent their own write
ordering, and a retried brief records the same trigger twice.

**F2. There is no brief threshold anywhere in the code, and the one threshold
that exists is a different quantity.** Design §6:275-277 says an active tag
lowers that counterparty's brief threshold and that the engine exposes the
current threshold as a query; §8:330-334 says both numbers live in a versioned
policy file. `Policy` (`tagging/src/policy.ts:22-82`) carries no brief
threshold, no active-tag factor and no relatedness floor. The only threshold in
the tree is `tagThreshold` (`tagging/src/threshold.ts:77`), θ_tag in robust-z
units, applied per reading at ingest, stored nowhere, not per counterparty, and
lowered by nothing. The design's vocabulary has three thresholds and the code
has one.

**F3. The brief's "sources" requirement collides with retention by
construction.** Design §6:270-273 says each reason carries its sources. A tag
names only its opening observation — `observation_id` is identity, frozen by the
guard (`0007:212-220`) — and `refresh` writes four fields and never the
observation (`store/src/repositories/tag.ts:231`), so a tag refreshed forty times names one observation
and the store records the other thirty-nine nowhere. Worse: `source.ref` is
inside the sealed payload (`store/src/repositories/observation.ts:228`), the calibrated half-life is 14
days (`calibration.ts:116`) and the retention grace is 90 days past the month
(`retention.ts:120`), so **every tag older than roughly four months is live with
an unreadable source**. And `listLive` has no shred gate, so an erased
namespace's tags come back and every source read raises `NamespaceShredded`.

**F4. Relatedness cannot be computed today, and the missing half is a data
model.** Nothing in any `src` computes it. Aspect matching has its inputs: the
tag row carries `channel` and `aspect` (`0007:143`) and the intent's reading
comes from `readObservation` (`tagging/src/reading.ts:138`). The entity graph
does not: a continuity assertion — the thing that links a wallet to the endpoint
whose payment address it is — is provenance INSIDE the sealed payload
(`schema/src/namespace.ts:54`), the `namespace` table holds `kind`, `ns_id` and
the key and nothing else (`0001:26-32`), and no table links two namespaces. M1's
own story links WALLET to PROVIDER only inside one observation's payload
(`store/src/acceptance.test.ts:123-139`) — unreachable without decrypting and
unreadable once that month expires. So relatedness today is at most (same
namespace) × (channel/aspect agreement).

**F5. "The condition is logged" has nowhere to go when the store is
unreachable, and the `tier` column cannot hold the risk tier.** The only log
this system has is the audit chain, in the same Postgres as every store
(`db.ts:105`). A connection failure carries no SQLSTATE, so `mapPgError` returns
null (`errors.ts:210`) and it surfaces as a raw driver error. Separately, the M1
spec welded "tier" to the tiered failure policy (`specs/2026-09-07-m1-stores-design.md:397`) and
`db.ts:147` repeats it, but `trigger_event_tier_needs_harm` (`0006:82`) refuses
a tier on any status but `harm_confirmed`, and a brief records a *candidate*
trigger (design §7:298). The evidence tier (A/B/C) and the intent's risk tier
(low/mid/high) are two different things in one column's mind.

**F6. "Recent permanent records" cannot be read.** Design §6:265 asks for them.
`PermanentRecordRepository` has `promote`, `read(recordId)` and
`get(recordId)` and no listing by namespace; `TriggerEventRepository` has
`record` and `get`. The M1 ledger recorded that the nightly read would want
indexes on the namespace columns of `trigger_event`, `hot_window` and
`permanent_record` (`ledgers/2026-09-06-m1-decisions.md:246`) and none landed.

**F7. The store's public surface cannot construct a `Db`, and the storage card
recorded that finding backwards.** `store/src/index.ts` exports no `db.js`, and
every repository constructor takes a `Db`. Measured on the built package:
`dist/index.d.ts` contains none of `openDb`, `withIsoDates`, `Schema`, `Db`. The
entry handed to M3 (`storage-card.md`, the "not fixed" block) said `export *`
carries those names OUT past the header's rule; the opposite shipped. Two true
facts sat under the false one: `package.json` has no `exports` field, so
`@nonametrust/store/dist/db.js` is deep-importable and the surface is a
convention rather than a boundary; and `retention.ts` is already exported with a
comment making exactly this argument one value short of its conclusion.

**F8. Two scenarios, and they disagree on four numbers.** Design §9:354-362 has
500 units and a `hold`. M2's corpus has one `endpoint` namespace, a 500-unit
quote and a 14-day half-life. M1's story has endpoint plus wallet linked by a
continuity assertion, 2500 USDC, `HALF_LIFE = 7 * DAY` "as tag.test.ts and
strength.test.ts assume", and a hand-chosen g0 of 0.6. And design §8:338-339
says the defaults are "chosen to make the Section 9 scenario behave" — a fitted
number by construction, which is the failure mode this project's own memory
names. M3's acceptance test must not pick numbers to pass.

**F9. "The nightly job is the only writer" is already false.** Design §2:71-74.
`refresh` writes `g0` per decision and the synchronous ingest path writes tags
and baselines. Determinism (design §9:367) has to be claimed over the ingest
path too, not only over the nightly pass.

**F10. The M2 ledger tells M3's engine to check that a state still holds, and
the root gate forbids the read.** M2 ledger 648-660. `gates/single-date-reader.test.ts:52`
scans every `packages/*/src` with no exemption for an engine and refuses any
line naming `validUntil`; `datedAt` (`schema/src/timing.ts:8`) returns null for
a state and exposes nothing about its interval. So a state whose validity ended
keeps opening and refreshing tags until either `schema` gains a second reader or
the gate gains an exemption.

**F11. Volatility is assigned to three different milestones.**
`store/src/repositories/volatility.ts:6` says "Mean-reverting in M3"; the M1
spec says M2; the M2 spec says "M3 and M4". The M3 card names none of them, and
the code holds a bare upsert with no arithmetic.

**F12. A candidate trigger needs a finite surprise and a categorical decision
has none.** `trigger_event.surprise` is `not null` and finite (`0006:77`);
`TagDecision.surprise` is null for every categorical reading (`tagging/src/tag.ts:202`).
If the brief builds a candidate trigger from the intent's own reading and the
intent is categorical, there is nothing to store.

**F13. A state's reason has no "original timestamp".** Design §6:272 says each
reason carries one. A state's tag is stamped at `at` and moves every morning,
and its row has `dated_at` null (`0002:39`). The reason shape must admit a
reason with no instant.

**F14. `BaselineRepository.upsert` loses a concurrent fold, silently, and it is
measured.** It is `on conflict do update set` with no predicate — last-writer-wins.
Measured during the survey: two writers each read `count = 10`, each folded one
observation and upserted `count = 11` with a different mean, both statements
succeeded, and the row ended at `count = 11` with one observation's contribution
gone and no error. It is latent today only because nothing outside tests calls
`upsert`; M3's engine is what makes it reachable, on the ordinary path.

## 2. Rulings this plan makes, so no implementer has to

**R1. The brief is a pure function that returns a value AND a list of effects; a
thin wrapper performs them.** Closes F1. It takes its instant, its generated
ids and its policy as inputs — so it calls no clock and no `randomUUID`, and
the same inputs replay to the same output, which is what design §9:367's
determinism claim needs. The effects are a `TriggerToRecord` and an
`AuditBodyToAppend`, in that order, and the audit body names the trigger id
because the core minted it as an input rather than the writer discovering it.
Cost if wrong: three wrappers still share one ordering, which is the point, but
a caller who ignores the effects gets a brief that answered and recorded
nothing — so the wrapper is the supported entry point and the core is exported
for tests and replay only.

**R2. The brief's numbers live in a third versioned value, `BriefPolicy`, in
`packages/engine`.** Closes F2. Not added to `Policy`: `Policy` is the tagging
package's and the brief is the engine's, so a brief field there is a number that
package never reads. And the M2 collision map (`ledgers/2026-09-12-m2-decisions.md:517-527`) has
`thresholdBase = surpriseScale = winsorMadMultiple = 3`, so a brief threshold
read off the wrong field would be invisible under a default policy — a separate
value removes that class of bug rather than testing for it. Cost: R7's "the
audit body names both versions" becomes three, and the champion-challenger key
becomes a triple. Recorded as a cost, not hidden.

**R3. "Active" is `strengthAt(tag, at) >= activeFloor`, not "live".** Closes
half of F2. Nothing retires a tag, `listLive` returns every tag ever opened, and
`strengthAt` reaches exactly zero only after about 1074 suppressed half-lives —
so "active = live" means every tag lowers the threshold forever and the threshold
means nothing. `activeFloor` is declared and uncalibrated and says so.

**R4. "Lowers" is multiplicative, not subtractive.** The threshold is an amount
in value units; a subtraction has to name a currency and a factor does not. Two
active tags compose by multiplying. Cost: a factor cannot express "never above
X regardless", which a subtraction can; if that is wanted it is a separate cap
and not this number.

**R5. These three numbers are fitted to the scenario and the plan says so.**
Design §8:338-339 already admits the defaults were chosen to make §9 behave.
This plan does not repeat that as though it were a derivation: §6 below lists
`briefThreshold`, `activeTagFactor`, `relatednessFloor` and `activeFloor` as
declared, uncalibrated, and re-derivable when the shadow evaluation measures a
population.

**R6. The risk tier is an enum on the brief's input, recorded in the audit body
only.** Closes half of F5. Not a column on `trigger_event`:
`trigger_event_tier_needs_harm` refuses a tier on a candidate, and the evidence
tier and the intent's risk tier must not share a column — that conflation is
already written into two documents and one type, and this plan stops it
spreading. Cost: the tiered policy is auditable through the chain and not
queryable by SQL; M4 may want a column and that is M4's migration.

**R7. "Unavailable" is a named set, and the log does not go to the audit
chain.** Closes the rest of F5. Unavailable is: a driver error with no SQLSTATE,
`Cancelled` (55P03/57014), `Deadlocked` (40P01), and a timeout the engine sets
itself. The condition is written to structured stderr, because the audit chain
lives in the same Postgres that is unavailable, and a reconciliation audit row
is appended when the store returns. The result carries its own code and is not
`hold`, because design §6 says error states are codes and not prose.

**R8. The medium tier's ceiling is an amount on the brief's input.** The engine
reads no amount today: `salienceHints` is read by nothing (M2 ledger 741-743).
So "medium passes under a ceiling" needs the intent's amount and its unit passed
in, declared as part of the brief's input shape rather than inferred.

**R9. `upsert` becomes optimistic and raises `BaselineStale`.** Closes F14. The
predicate is the `n` the caller read. Chosen over a per-pair advisory lock in
the engine because the advisory key space is already shared and unallocated
(storage card's own "not fixed" list) with a measured deadlock history (R20),
and because an optimistic `n` keeps every store write a single statement that
composes under R21. Cost: the retry loop now has two stale signals to handle,
and that is written into R10 rather than discovered.

**R10. The retry loop re-reads the baseline AND the live tag, and the write
order is baseline first.** `decide` is a function of `observation`, `at`,
`liveTag` (including its decayed strength), `policy`, `calibration`, and of
`g0`/`surprise`/`crossed`, which `tagReading` derives from the baseline. So a
retry that re-reads only the tag folds the same observation in twice. Baseline
first because the decision depends on the folded baseline: tag-first would
decide against a stale one, and a retry after a baseline failure would leave a
tag decided on a baseline that never landed. A "new" decision can lose its race
too — 23505 on `tag_one_live_per_pair` — and retries as a refresh.

**R11. Relatedness across namespaces needs a table, and `0008` adds it.**
Closes F4. `namespace_link (from_namespace_id, to_namespace_id, kind,
asserted_by, asserted_at, reason)`, written at ingest when an observation
carries a continuity assertion, with the assertion's own provenance in the
clear. The argument is the one that put `producer` and `period` in columns: a
continuity assertion is not payload, it is a fact ABOUT the row, and
"the provider's payment address moved" is meaningless if the link to the
provider dies with the month. **And the privacy cost is real and goes in §2c's
list:** after an erasure the link survives and says that this wallet was
asserted to be that endpoint's payment address. That is a graph in the clear and
the erasure-survivors enumeration gains it, beside `tag.aspect`.

**R12. Relatedness itself is (link distance) × (channel/aspect agreement), and
nothing more in M3.** No clustering, no inferred edges, no `cluster_id` —
that column stays null and M4 owns it. A link is an assertion someone made;
M3 never infers one.

**R13. A reason whose evidence is unreadable is KEPT, with a code.** Closes F3.
`SOURCE_UNREADABLE`, carrying the columns that survive in the clear:
`dated_at`, `channel`, `aspect`, `evidence_kind`. Omitting the reason would make
the brief's answer change as retention runs — the output would depend on the
calendar rather than on the evidence, which is the worst of the three options.
Refusing the brief is worse still. **And this is an outward claim:** the brief
can cite a reason older than about four months without its source, and that
sentence belongs in the README and the whitepaper rather than being discovered
by a user.

**R14. `listLive` gains a shred gate at the engine, not in the store.** An
erased namespace's tags come back today and every source read raises
`NamespaceShredded`. The store's `listLive` keeps answering, because a caller
asking "what tags exist" is entitled to the skeleton; the engine refuses to
brief on an erased namespace by name, before it reads a tag.

**R15. The acceptance scenario is M1's story with the CALIBRATED half-life.**
Closes F8. Endpoint plus wallet linked by a continuity assertion, 2500 USDC, and
14 days — not 7. The wallet link is what makes relatedness non-trivial, which
is the criterion this milestone exists to prove, and 14 days is the product's
number. The store's own acceptance test keeps 7 days for its own reasons and the
plan records why the two differ instead of unifying them.

**R16. The state-validity check lives in the engine, and the root gate gains one
named exemption.** Closes F10. Named by file, the same shape as the clock gate's
two exemptions. A second date reader in `schema` would put the interval in two
places, which is what the gate exists to prevent.

**R17. Volatility and the hot window are M4's, and this plan says so once.**
Closes F11. Three documents disagree; the brief reads no volatility, and the
nightly job is what would maintain it. M3 touches neither.

**R18. A categorical intent builds no candidate trigger.** Closes F12. The
trigger's `surprise` is not null and a categorical reading has none, so the
brief returns its grade with no trigger effect rather than inventing a number.
Cost: a categorical intent is not counted in the trigger table; M4's
consolidation reads tags, not triggers, so nothing downstream breaks.

**R19. The reason shape admits a reason with no instant.** Closes F13. A state's
reason carries `datedAt: null` and says so in its code rather than borrowing the
tag's moving `tagged_at`.

**R20. `index.ts` exports `openDb` and the `Db` type, and its header sentence
changes.** Closes F7. Measured: the surface as declared cannot construct a
repository. Deep-importing `dist/db.js` would make the boundary a fiction, and
`retention.ts` was already exported on exactly this argument. The sentence
becomes "repositories, errors and the connection are exported; the SQL is not".

**R21. A per-observation refusal is recorded as a code and an observation id,
never as the message.** `surpriseOf`'s `RangeError` carries the observed value
(`tagging/src/scale.ts:63`), and an audit body outlives both the month key and
the namespace key (F7 of the storage card: the chain hashes the caller's body
and no ciphertext digest). So the code goes in and the message does not.

## 3. Global constraints for every task

- **The engine is the only module that may import both packages.** A root gate
  holds it: nothing in `packages/store/src` imports tagging, nothing in
  `packages/tagging/src` imports store, and only `packages/engine/src` imports
  both.
- **The engine computes nothing a decision depends on.** It composes. `g0`,
  `taggedAt`, the saturation state and the surprise all come from M2 and are
  passed to the store as handed — which is the storage card's corrected version
  of "the store computes nothing".
- **`at` is the engine's clock on every path, including replay**, and it is the
  same `Clock` object the store holds: `open` and `refresh` refuse a `taggedAt`
  after `clock.now()` (R12 of M2), and the store's own constructor now refuses a
  clock that is not its namespace repository's.
- **Every refusal names its field or its class.** A brief that fails must say
  which store, which tier and which code.
- **Assert a refusal's message or constraint name, not only its class** — the
  M2 ledger's test habit, which caught four rules on the storage card.
- **Override every `BriefPolicy` field in at least one test with a number no
  other field shares.** The M2 collision map is why: three of its fields were 3.
- **For every test in a brief, delete the line it claims to protect and confirm
  the test fails.** Report any that stay green.

## 3b. The mutation step is not optional

After a task is green: remove each rule one at a time and RECORD which test goes
red. A surviving mutant is an unheld rule. Three lessons this repository paid
for, in order of how much they cost:

1. **When a mutant dies, ask WHICH test killed it.** A test of another rule
   going red is not evidence. This was got wrong once and written into a commit
   message as "measured".
2. **Mutate both sides of a binding consistently as well as separately.** A
   consistent rename passes every round-trip test.
3. **Colliding fixture values make a rule invisible.** Four times on the storage
   card, once because `shredded_at` and `expires_at` were the same instant in the
   only test that asserted either.

And re-run the mutants this plan's own earlier tasks claim, at the end. On the
storage card, 145 re-run mutants found four killers that had stopped killing —
one disarmed by a later task adding a second call a stub did not cover.

## 4. Tasks

### Task 1: `packages/engine`, the import gate, and `BriefPolicy`

**Does:** the package with `store` and `tagging` as dependencies; `BriefPolicy`
with `version`, `briefThreshold`, `activeTagFactor`, `activeFloor`,
`relatednessFloor` and `assertBriefPolicy` refusing each field by name; a root
gate `gates/engine-is-the-only-composer.test.ts` that scans all four packages'
`src` and refuses a cross-import outside `packages/engine/src`, with its own
planted-violation self-checks.

**Acceptance:** the gate goes red on a planted `import ... from "@nonametrust/tagging"`
inside `packages/store/src`, and on a planted store import inside tagging; every
`BriefPolicy` field is refused by a message naming it; the four numbers are
declared uncalibrated in the doc comment with their sources or the absence of
one.

### Task 2: the store's surface, and `BaselineStale`

**Does:** R20 — `index.ts` exports `openDb` and the `Db` type and its header
sentence changes; the surface pin moves. R9 — `BaselineRepository.upsert` takes
the `n` the caller read and its UPDATE pins `n = expected`, raising
`BaselineStale` on zero rows with a follow-up select distinguishing it from a
missing row, exactly as `refresh` distinguishes `TagRefreshStale` from
`TagNotFound`.

**Acceptance:** two concurrent folds on one pair produce one success and one
`BaselineStale`, measured the way the twenty-concurrent cap test is; the lost
update measured in F14 no longer happens; deleting the predicate turns that test
red.

### Task 3: `0008`, `namespace_link`, and the erasure-survivors list

**Does:** R11. The table with its own guard (no DELETE, identity fixed,
`asserted_at` forward-only), a unique index on
`(from_namespace_id, to_namespace_id, kind)`, and both foreign keys. A
`NamespaceLinkRepository` with `assert` and `linkedTo`. And §2c of the storage
card's plan gains the disclosure: after an erasure the link survives and says
this wallet was asserted to be that endpoint's payment address.

**Acceptance:** the guard refuses each rule by name from a raw writer; a link
survives a namespace shred and a month sweep; the README's erasure paragraph
names it beside `tag.aspect`.

### Task 4: relatedness

**Does:** R12. A pure function over a link set and two readings. No clustering,
no inference, `cluster_id` untouched.

**Acceptance:** an aspect match inside one namespace scores above the floor; a
link of distance one with a matching channel scores above it; a link with no
channel agreement does not; an unlinked namespace scores zero. Each number in
the test is chosen to differ from every other so a swapped field is visible.

### Task 5: the brief, as a pure function with effects

**Does:** R1, R13, R18, R19, R21. The core takes `{ at, briefId, triggerId,
observationId, amount, unit, riskTier, policies }`, reads through repositories
handed to it, and returns `{ grade, reasons, sources, effects }`. Reasons carry
a code, and `SOURCE_UNREADABLE` when the payload will not open. The wrapper
performs the effects in order.

**Acceptance:** the same inputs replay to the same output, asserted by running
it twice against a frozen database; a reason whose month has expired comes back
with its code and its clear columns rather than throwing or vanishing; a
categorical intent returns a grade and no trigger effect; the core called
directly writes nothing, measured by comparing every table's `xmin`.

### Task 6: the threshold, and what an active tag does to it

**Does:** R3, R4. `thresholdFor(namespaceId, at)` as the query design §6 asks
for, and the brief's use of it.

**Acceptance:** a tag at `activeFloor` exactly is active and one a millisecond's
decay below it is not; two active tags compose multiplicatively; a live but
inactive tag changes nothing; the threshold query and the brief agree, asserted
by reading both.

### Task 7: the risk tier and the unavailability policy

**Does:** R6, R7, R8. The tier enum on the input, the audit body, the named
unavailable set, the structured log, the reconciliation row, and the codes.

**Acceptance:** each of the four unavailable conditions produces its code and
its log line, with the store actually unreachable rather than stubbed — a
connection to a port nothing listens on, a `lock_timeout` of 50ms behind a held
lock, a deadlock, and an engine timeout; low proceeds and logs, medium passes
under the ceiling and refuses above it, high holds; the reconciliation row
appears when the store returns and names what it reconciles.

### Task 8: the ingest path

**Does:** R10, R16. `observe(wire, at)`: validate, fold the baseline, decide,
write, with the retry loop and the state-validity check. The root gate gains its
one named exemption.

**Acceptance:** forty concurrent observations on one pair produce forty folds and
no lost update; a `BaselineStale` retry does not double-fold, asserted on the
count; a `TagRefreshStale` retry re-reads both and decides again; a state whose
validity ended opens no tag; the gate's exemption is named and its
"the exemption is doing work" test is non-vacuous.

### Task 9: acceptance

**Does:** R15. The day-zero / day-twelve / day-twenty-one story end to end
through the engine, on one database, with the calibrated half-life: the address
moves and reverts, the tag opens into limbo and refreshes, the large quote
arrives, the brief returns a graded answer whose reason is dated day twelve and
whose source opens, and the provider's threshold is lower than it was because
the tag is active.

**Acceptance:** the whole file green; every number in it derived rather than
chosen, or marked as chosen with the reason; the brief's answer asserted from
the brief and not from the array the test filled earlier — the trap the storage
card's own acceptance test fell into twice.

## 6. The uncalibrated inputs, declared

`briefThreshold`, `activeTagFactor`, `activeFloor`, `relatednessFloor`. Four
design numbers, none measured, all re-derivable when the shadow evaluation
measures a population. Design §8 admits its own defaults were chosen to make §9
behave; this plan does not improve on that by pretending otherwise. Each gets a
doc comment saying what it is, what it is not, and what would replace it.

## 7. Open questions for Kerem

- **The brief's output shape is fixed "by the founder brief" (design §6:270) and
  no document in this repository carries it.** The grade vocabulary — `hold` is
  the only named value — the reason codes and the error codes are not in the
  tree. Ruled provisionally: `clear | watch | hold`, with the codes this plan
  names. Veto before Task 5.
- **One package or two.** Design §2:59-60 names `engine` and `nonametrust`;
  `README.md:25` says both arrive in later milestones. This plan builds one,
  `engine`, and leaves the distribution package to M5.
- **The latency budget is unmeasured.** Design §2:45 says one to two seconds,
  and a brief over N live tags costs one AEAD open plus one key unwrap per
  reason with a source. Measured in Task 5 and reported; if it exceeds the
  budget the reason count is capped and the cap is a policy number.

## 8. Risks: where a plausible implementation is silently wrong

- **A retry that re-reads the tag and not the baseline.** Folds the same
  observation twice, and the count is the only witness. G12.
- **A brief that reads the threshold it just lowered.** The threshold query and
  the brief must read one value at one instant; two reads at two instants make
  the answer depend on how long the brief took.
- **`activeFloor` as a float comparison at exactly the floor.** The storage
  card lost four rules to fixture values that coincided; here the floor and the
  decayed strength will coincide unless the test chooses them not to.
- **A reason omitted rather than coded when its source is unreadable.** The
  brief's answer then changes as retention runs and nothing fails.
- **The engine's clock and the store's clock being two objects.** The store now
  refuses that between two of its own repositories; the engine must pass the
  same object down or it will be refused at construction — which is the good
  case. The bad case is passing `new Date()` somewhere, which the clock gate
  catches only inside `packages/store/src`; the engine needs its own gate entry.
- **`namespace_link` treated as inference.** A link is an assertion. The moment
  the engine writes one it did not read from a payload, the identity model's
  central sentence — an address is an attribute of a counterparty, and the two
  are linked by an assertion and never inferred — stops being true.
